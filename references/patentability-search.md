# 查重检索与授权可能性评估

## 1. 适用场景

当用户要求以下任一任务时，执行本流程：

- `查重`
- `检索`
- `授权可能性`
- `现有技术对比`
- `最接近专利`
- `审查风险`

## 2. 基本原则

1. 必须联网检索并给出来源，不能只凭记忆判断。
2. 优先使用专利文献原始来源或高可信专利聚合来源，其次再用论文或公开技术资料补充。
3. 评估不能只看是否有一篇“完全一样”的文献，还要看审查员是否容易通过两篇或多篇文献组合攻击创造性。

## 3. 检索准备

对每篇交底书先抽出这六项：

- 发明名称
- 核心对象
- 关键输入
- 关键输出
- 真正的新颖性锚点
- 最像现有技术的基础方向

然后构造中英文关键词：

- 业务对象词
- 技术机制词
- 信号或数据源词
- 判定或建模词
- 约束和输出词

## 4. 检索执行

每篇至少执行以下几类检索：

1. 以发明名称核心名词为中心的中英文检索
2. 以关键机制为中心的检索
3. 以数据源组合为中心的检索
4. 以输出结果和约束方式为中心的检索
5. 去掉业务词后的抽象机制检索
6. 用最接近的已发现文献反向扩展检索

## 5. 结果筛选

优先保留这些文献：

- 与本发明对象相同
- 与本发明关键机制相同或高度相似
- 与本发明判定链或建模链相似
- 可与其他文献组合后逼近本发明

对每篇候选文献，至少记录：

- 标题
- 链接
- 公开/授权状态
- 最相关的技术点
- 与本发明相同之处
- 与本发明差异之处

## 6. 评估输出结构

每篇报告建议固定为：

1. 核心创新点摘要
2. 最接近现有技术
3. 新颖性判断
4. 创造性风险
5. 可能的组合攻击路径
6. 最该保住的技术特征
7. 当前保守授权概率区间
8. 申报优先级建议

## 7. 风险判断口径

### 7.1 新颖性压力较大

通常对应以下情形：

- 已找到单篇文献覆盖主要技术链
- 仅剩少量工程细节差异
- 差异点更像参数调整而非新的技术机制

### 7.2 创造性压力较大

通常对应以下情形：

- 核心步骤可由两篇常见文献直接拼接
- 差异点属于显而易见的工程优化
- 数学表达只是重新描述常规规则

### 7.3 授权前景较好

通常对应以下情形：

- 找不到单篇近似文献
- 组合攻击需要跨多个方向且缺乏明确动机
- 本发明有稳定的核心锚点，可被写入独立权利要求

## 8. 报告书写要求

- 结论先行
- 先写风险，再写总结
- 明确区分“已发现文献直接覆盖”和“可能被组合攻击”
- 必须点出最值得保住的技术特征，方便后续权利要求布局
